### 설계 원칙 세 가지

1. **배선은 한 곳** — dcode 소스 수정은 `agent.py` 미들웨어 목록 한 줄. 나머지는 전부 `assistant/`
2. **지침과 강제를 나눈다** — `AGENTS.md`는 부탁, 실제 차단은 미들웨어 코드 (8일차 6p)
3. **판정 실패를 통과로 읽지 않는다** — 로거·게이트가 죽으면 차단 또는 검토 (8일차 22p, fail-closed)

### 단계 2 — 이벤트 로거 (내일 오전, 3시간) → 항목 4

**먼저 하는 이유** — 로깅이 깔려야 그 다음에 만드는 것들이 뭘 하고 있는지 보인다. 그리고 항목 4의 10점을 거의 그대로 가져가면서, 파이썬 코드가 남아 항목 1에도 쓰인다.

`assistant/observability.py` — `AgentMiddleware`를 상속해 각 시점에 기록.

| 기록할 것 | 어느 Hook | 채점 항목 |
|---|---|---|
| 요청 시작·사용자 입력 | `before_agent` | 4-1 |
| 모델 호출 전후, 토큰·지연 | `wrap_model_call` | 4-2, 4-3 |
| 도구 실행·결과·오류 | `wrap_tool_call` | 4-1, 4-2 |
| 종료·최종 결과 | `after_agent` | 4-1 |

출력: `runs/<run_id>/events.jsonl` — 한 줄에 한 이벤트.

`assistant/report.py` — run 목록, 타임라인, **실패 지점**, 지표 집계 (4-3, 4-4).

**완료 조건** — TUI에서 아무 작업이나 시킨 뒤 `report.py`로 그 작업의 흐름과 소요 시간이 보인다.

### 단계 3 — 계획 게이트 (내일 오후, 4시간) → 항목 2

배점 10점 중 가장 비어 있는 곳이자, 강사가 수업에서 가장 강조한 부분.

> 🎤 "최종 ok된 계획만 개발에 쓰이도록 해야 한다. 그 외 개발작업이 되면 제대로 구현 못한 것이다. 통제가 필요하다."

**설계**

1. **계획 문서 강제** — 스킬로 템플릿 제공: 요구사항 / 범위 / 완료조건 / 수정 대상 파일 목록 / 작업 순서 / 테스트 방법 (2-1, 2-2)
2. **AI 리뷰** — plan-reviewer 서브에이전트가 계획을 비평 → 수정 반영 (2-3)
3. **승인 게이트** — `assistant/plan_gate.py`가 `wrap_tool_call`에서 쓰기·실행 도구를 가로챈다 (2-4)
   - 승인된 계획이 없으면 **차단**
   - 승인된 계획의 **파일 목록 밖**이면 차단 → 범위 변경으로 간주, 재검토 요구
4. dcode의 `/goal`(수용 기준 초안 → 인라인 리뷰 → 승인)을 함께 쓴다

**완료 조건** — 승인 없이 코드 수정을 시키면 차단되고, 로그에 차단 사유가 남는다. (AC2)

⚠️ 8일차 43p: **차단·검토·판정 오류에서 실제 구현 함수가 호출되지 않는지 테스트**한다 → `tests/`

### 단계 4 — 메모리·자기개선 (모레 오전, 4시간) → 항목 3

| 항목 | 구현 |
|---|---|
| 3-1 저장·유지 | `.deepagents/AGENTS.md` + `memories/*.md`. 세션 넘어 유지 |
| 3-2 검색·활용 | 계획 작성 전 메모리 검색을 **절차로 강제**하고, 검색한 사실을 **로그에 남긴다** (4-2와 연결) |
| 3-3 개선안 생성 | 실패·차단 이벤트를 모아 임계치 초과 시 개선안 자동 생성 |
| 3-4 **전후 검증** | 개선안 적용 **전/후를 같은 조건에서 비교**하고, 통과한 것만 반영 |

⚠️ **TCB(6일차)** — 자기개선이 **못 고쳐야 하는 것**: 평가기, 테스트, 계획 게이트, 권한 정책, 감사 로그. 개선안이 테스트를 지워서 통과율을 올리는 걸 막는다.

⚠️ **3-4가 다들 빠뜨릴 부분이다.** 7일차 실습 Task 2에서 한 **같은 런 안 OFF/ON 비교**가 여기 그대로 쓰인다. 어제 잰 값을 오늘의 기준선으로 쓰지 않는다.

**완료 조건** — 세션1에서 규칙을 가르치면 세션2에서 적용되고, 실패가 반복되면 개선안이 자동으로 쌓이며, 적용 전후 비교 결과가 로그에 남는다. (AC3)

### 단계 5 — PEP8 + README + 최종 점검 (모레 오후, 5시간) → 항목 1, AC1·AC5

1. **`pyproject.toml`의 ruff 설정** — `E`(스타일) + `I`(import 정렬) + `N`(명명) + **`D`(docstring)**. 1-1·1-2·1-3이 여기 대응
2. **`assistant/style_gate.py`** — `PostToolUse` 성격으로, 파일이 쓰인 뒤 ruff 검사 → 실패 시 피드백
   - ⚠️ 기존 `pep8_gate.py`는 `Write`만 검사해 `edit_file`에 구멍. **파일을 직접 읽어서 검사**하는 방식으로 바꾼다
3. **내 코드 전부에 docstring** — 채점자가 읽는 건 `assistant/`다
4. **README 재현 절차** — 항목별 테스트 케이스 4개. 채점자가 그대로 따라 할 수 있게
5. **깨끗한 환경에서 처음부터 재현** — 다른 디렉터리에 clone해서 README만 보고 실행
